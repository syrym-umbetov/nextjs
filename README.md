# Тренажёр по документации Next.js

Вопросы по App Router с разбором и ссылкой на конкретный раздел документации.
Вопросы возвращаются по алгоритму SM-2, прогресс хранится в localStorage браузера.

Бэкенда и базы данных нет: `next build` собирает приложение в статику (`out/`),
которая разворачивается на Vercel как есть.

## Стек

Next.js 16.3 (App Router) · TypeScript в строгом режиме · Tailwind CSS 4 ·
Shiki для подсветки кода · Vitest.

Состояние сессии — `useReducer`, внешних стейт-менеджеров нет. Схемы описаны
через zod и используются и на сборке, и в рантайме.

## Команды

```bash
npm install
npm run dev        # сборка контента + дев-сервер
npm run build      # сборка контента + next build → out/
npm test           # vitest
npm run typecheck  # tsc --noEmit
npm run content    # только пересобрать контент
```

## Контент

Вопросы лежат в `content/questions/<topic>.json`, где имя файла совпадает с полем
`topic` каждого вопроса внутри. Схема — `lib/question.ts`.

`scripts/build-content.ts` выполняется перед `next dev` и `next build` (npm-хуки
`predev` / `prebuild`) и делает три вещи:

1. **Валидирует** каждый вопрос через zod и проверяет инварианты между файлами:
   уникальность `id`, совпадение `topic` с именем файла, существование
   `correctOptionId` среди вариантов, принадлежность `docsUrl` к `nextjs.org/docs`.
   Любая проблема завершает процесс с кодом 1 — билд падает, битый вопрос до UI
   не доезжает.
2. **Подсвечивает код** через Shiki на этапе сборки, так что ни грамматики, ни
   тема подсветки в клиентский бандл не попадают.
3. **Раскладывает статику** в `public/content/` (каталог генерируемый, в git не
   хранится):
   - `index.json` — `{ id, topic, difficulty }` для всех вопросов;
   - `q/<id>.json` — полное тело вопроса с готовым HTML подсветки.

Такое разделение решает конфликт между «в клиент уходят только вопросы сессии» и
«подбор зависит от localStorage»: планировщику хватает лёгкого индекса, а тела
вопросов браузер докачивает только для тех десяти, что попали в сессию.

### Добавить вопрос

Дописать объект в соответствующий файл `content/questions/*.json` и запустить
`npm run content`. Скрипт скажет, что не так, если схема нарушена.

Поле `nextVersion` обязательно: поведение кэширования и умолчания менялись между
версиями, поэтому у каждого вопроса зафиксировано, для какой версии ответ верен.
Текущий контент сверен с исходниками документации на теге `v16.3.4`.

## Интервальное повторение

`lib/srs.ts` — реализация SM-2 из чистых функций: ни localStorage, ни системных
часов, ни мутаций аргументов. Текущий день передаётся параметром, поэтому модуль
покрывается тестами без моков (`lib/srs.test.ts`).

`lib/select.ts` подбирает сессию: сначала карточки со сроком `dueDate <= сегодня`
(самые давно просроченные первыми), затем добор новыми вопросами от простых к
сложным до десяти. Если долгов больше лимита, новые не добавляются.

Шкала 0–5 достраивается из «верно / неверно» временем ответа
(`gradeFromAnswer`): быстрый верный ответ — 5, долгий — 3, неверный — 1.

## Структура

```
content/questions/   исходные вопросы (JSON)
scripts/             валидация и сборка контента
lib/                 схемы, SRS, подбор сессии, редьюсер, хранилище
app/                 Server Components; "use client" только в _components/
```

Граница клиентских компонентов держится максимально низко: главная страница и
оболочка сессии — Server Components, интерактивность вынесена в отдельные
компоненты внутри `_components/`.
